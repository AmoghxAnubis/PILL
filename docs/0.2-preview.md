# PILL 0.2 development preview

## Use this preview

Close older PILL and PILL Control processes before starting the rebuilt applications together. This preview uses settings schema version 2; existing version-1 preferences are migrated in memory and preserved when the next change is saved. Version 0.2.0 is a preview; the 0.2 release gates are not yet complete.

The native overlay is built at PILL/archipelago/src-tauri/target/debug/PILL.exe. The matching Control application is at PILL/pill-control/src-tauri/target/release/PILL-Control.exe. Build outputs are ignored by Git.

Hover or click the clock, or focus it and press Enter, to expand. The tabs offer Calendar, Weather, Media, Focus and System. Arrow keys move between tabs. Right-click, press Shift+F10, or use the header's Quick settings button to open the customization surface. Escape closes that surface first; pressing Escape again collapses the dashboard. Clicking outside the application dismisses quick settings when the window loses focus.

Pin, theme, background opacity, shape, size and pointer-expansion preferences are saved. The background fades independently of text. Fluent inspired is a color preset; it does not claim native acrylic. Scaling changes both the rendered island and native window dimensions. Pinning does not override fullscreen evasion. Explicitly collapsing a pinned island also saves the unpinned preference.

## Weather setup and data behavior

Open PILL Control from quick settings, select Weather, and search for a city. Search results include region/country so ambiguous names can be resolved. Selecting a result enables weather for that city. No automatic location detection is used. City searches and forecast retrieval send the entered query or selected city coordinates to Open-Meteo. Turning weather off stops future refreshes; an already-sent request can finish, but its obsolete result is ignored.

Choose Celsius with km/h or Fahrenheit with mph. Idle view shows the selected city's temperature when available; the expanded Weather card shows condition, feels-like, humidity, wind and the observation time. No weather values are simulated.

Normal refresh is every 15 minutes. Failed requests retry after 1, 2, 4 and 8 minutes, then at 15-minute intervals. A valid last reading stays visible with a Cached label on failure. Readings older than 24 hours are discarded. Cached data is matched to the exact selected location and units. Requests have connection/total timeouts and a response-size bound. The cache is local to the PILL application-data directory and holds the most recent successful reading.

Forecast data comes from [Open-Meteo](https://open-meteo.com/en/docs), with location search based on [GeoNames](https://www.geonames.org/). Weather data is used under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). The bundled free API endpoint is for non-commercial use; commercial distribution needs a suitable provider arrangement under [Open-Meteo's terms](https://open-meteo.com/en/terms).

## Persistence and checks

Both applications use the same Rust settings model/storage implementation. Partial updates merge into the latest revision under an operating-system file lock and are written by atomic replacement. Invalid values, corrupt files and unsupported future versions are rejected without overwriting the existing settings. A stale settings-monitor response cannot replace a newer overlay revision.

Automated checks cover migration, concurrent updates, invalid-file preservation, partial-write ordering, quick-settings keyboard/dismissal behavior, native/frontend scale alignment, cache fallback/expiry, disabling weather and late results from an old location. The native provider also passed a live city search and forecast request for the public example city Berlin.

Before release, verify both native windows on Windows: restart persistence; simultaneous Control/island changes; city selection and unit changes; offline cache labeling; mixed DPI/monitors; small work areas; fullscreen evasion; mouse/keyboard focus; reduced motion; and background opacity over light/dark windows. Native visual acceptance has not been established by DOM tests.

Idle hiding/reveal, monitor placement, tray/startup completion, provider suspension, live audio/FPS/download features and the optional assistant remain tracked in the main plan.
